# Autodiagnóstico — Aula 12 (Code Smells)

| # | Arquivo:linha | Smell (nome técnico) | Refactoring proposto | Justificativa |
|---|---|---|---|---|
| 1 | `services/servico_emprestimo.py` (topo da classe, antes do fix) | Duplicated Code / código morto | Remover o código duplicado | Havia três métodos (`registrar`, `devolver`, `listar_atrasados`) definidos duas vezes. A primeira definição de cada um nunca executava, continha variáveis indefinidas e chamava um atributo que não existe (`usuario_email` em vez de `email`). Consequência: o Observer da Aula 11 nunca notificava ninguém de verdade. Corrigido em commit `fix:`, separado dos `refactor:`, por alterar comportamento observável. |
| 2 | `services/servico_emprestimo.py` (chamadas a `self.notificar`) | Primitive Obsession | Replace Primitive with Object | O evento do Observer era um `dict` solto. Um erro de chave só aparecia em tempo de execução, e nenhuma definição documentava quais campos um evento tinha. Substituído por `Evento`, uma `@dataclass` tipada em `services/evento.py`. |
| 3 | `services/servico_emprestimo.py`, método `registrar` (parâmetro) | Mysterious Name | Rename | O parâmetro `dias` não dizia dias de quê. Renomeado para `dias_emprestimo` pela IDE (Rename Symbol / F2), que atualizou as duas referências no método automaticamente. |
| 4 | `services/servico_emprestimo.py`, método `listar_atrasados` | Long Method | Extract Function | O método misturava iteração, verificação de atraso, cálculo de multa e notificação num único bloco. Extraídos `_esta_atrasado` e `_processar_atraso` (cálculo + notificação), deixando `listar_atrasados` expressar só o fluxo principal. |
| 5 | `models/equipamento.py` — classes `Notebook`, `Projetor`, `Cabo` | **Smell aparente — não refatorado** (Data Class) | — | Essas subclasses ficaram vazias depois do Strategy da Aula 11, e à primeira vista parecem Data Class (sem comportamento próprio). Não devem ser refatoradas: existem por design, para que o sistema saiba o tipo de equipamento pelo próprio objeto, sem voltar a usar uma string/flag solta. Aplicar Inline Class reverteria o Strategy e o OCP conquistados na Aula 11 — qualquer novo tipo de equipamento voltaria a exigir editar um `if/elif` existente. |
