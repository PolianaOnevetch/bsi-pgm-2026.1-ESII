# ADR-001 — Arquitetura em Camadas

## Status

Aceito

## Data

2026-05-27

---

## Contexto

A versão inicial do sistema concentrava regras de negócio, armazenamento de dados e interação com o usuário em um único arquivo. Essa abordagem permitia uma implementação rápida, porém gerava problemas de manutenção, acoplamento excessivo e dificuldade para realização de testes.

Além disso, os requisitos RNF03 (manutenibilidade) e RNF04 (testabilidade) não eram plenamente atendidos pela estrutura existente.

---

## Decisão

Foi adotada uma arquitetura em camadas para a versão 2.0 do sistema.

A organização definida é:

* **models**: representação das entidades do domínio;
* **services**: implementação das regras de negócio;
* **repositories**: gerenciamento dos dados;
* **main.py**: interação com o usuário.

Também foram introduzidas interfaces para reduzir acoplamento e permitir substituição de implementações.

---

## Consequências

### Positivas

* Maior separação de responsabilidades;
* Facilidade para manutenção;
* Possibilidade de testes isolados;
* Menor acoplamento entre componentes;
* Melhor aderência aos princípios SOLID.

### Negativas

* Maior quantidade de arquivos;
* Estrutura inicial mais complexa;
* Necessidade de definir contratos entre componentes.

---

## Alternativas Consideradas

### Arquivo único

Mantém simplicidade inicial, porém não resolve os problemas identificados na versão anterior.

### MVC

Oferece boa separação de responsabilidades, mas adiciona complexidade desnecessária para uma aplicação de linha de comando.

### Arquitetura em Camadas

Foi considerada a alternativa mais equilibrada para o tamanho e os requisitos do projeto.
